# 2026-11 兼容性修复说明：新批次遥控器按键 + macOS 26 独占

本文记录一次完整的"普通按键失效"排查与修复。涉及两类互相独立的问题：**遥控器硬件批次差异**与 **macOS 26 系统策略变化**。所有结论均来自实机抓包与实测，样机边界见 [PROTOCOL.md](PROTOCOL.md)。

## 现象

- **症状 A**：遥控器配对成功、语音键完全正常，但普通按键检测计数恒为 0，从未收到任何一条按键。
- **症状 B**（修复 A 后）：接收日志里有"按下"记录，系统却没有任何动作，实际只有语音键可用。

## 根因一：按键报告布局随批次变化

新批次样机（VID/PID `18D1:9450` 相同，系统报告固件 **0.0.1**；首批为 26.7）的按键输入通知不在 `0x0046`，而在 **`0x002B`**，且格式不同：

| | 首批样机（固件 26.7） | 新批次样机（固件 0.0.1） |
| --- | --- | --- |
| 输入特征 handle | `0x0046` | `0x002B` |
| 报告格式 | 每字节一个 8 位数组索引（1–17） | 每 2 字节一个 16 位小端 Consumer usage |
| 单键报告 | 1 字节，如 `03` | 2 字节，如 `4200`（= 0x0042 方向上） |
| 和弦报告 | 2 字节，如 `03 0B` | 4 字节，如 `41004200`（两个 usage 码） |
| 松开报告 | `00` | `0000` |

两个字节对不上（handle 不同）+ 格式对不上（编码不同），解码器静默丢弃一切，症状 A 就此产生。新布局已实测验证 14 个实体键与首批索引表一一对应（0x41=确认、0x42–0x45=方向、0xE2=静音、0xE9/0xEA=音量、0x77/0x78=YouTube/Netflix、0x19E=电源、0x189=输入源、0x223/0x224=主页/返回）；首批的 0xCD/0x221/0x79 在本批次未出现，对应其没有这三个扩展实体键。

**修复**：解码器（`GooglePacketDecoder`）改为接受逗号分隔的多个候选 handle（`46,2B`），按 handle 区分两种布局规则；互不干扰，未列出的 handle 一律忽略（防止电池等其它特征误报）。

## 根因二：macOS 26 收紧 HID 独占

映射执行的前提是独占原生输入（`kIOHIDOptionsTypeSeizeDevice`），防止系统原生动作与映射双发。实测 **macOS 26.6** 上：

| 执行者 | `open(0)` | `open(seize)` |
| --- | --- | --- |
| 普通用户（uid 501） | 成功 | **`0xE00002C1` kIOReturnNotPermitted ❌** |
| root（uid 0） | 成功 | **`0x0` 成功 ✅** |

首批样机在 macOS 15.8.2 上普通应用独占成功；macOS 26 拒绝普通应用独占后，应用的独占分支失败且无重试，映射永久处于暂停状态——日志只登记、不执行，即症状 B。方向键"看起来能用"其实是系统原生识别了标准 Consumer 方向码，并非映射在工作。

**修复**：应用自身的独占逻辑移除，改由**本就以 root 运行的采集助手**在接收会话内执行独占，并经新增的 `seized` / `seize-failed` 事件同步给应用：

- 会话开始时独占所有 `18D1:9450` HID 设备，失败则事件上报、映射暂停（可重开接收重试）；
- 助手进程退出（正常停止/崩溃/被杀）句柄随之关闭，独占自动解除；
- 遥控器休眠重连后的新 HID 设备实例由 `IOHIDManager` matching 回调自动补独占。

应用的 Google IOHID 回调在此路径上原本只维护从未被读取的抑制时间戳（见 `shouldSuppress` 对 Google 的提前返回），独占移至助手后无功能损失；组合键、单键、松开全部仍由抓包解码器输出。

## 根因三：会话事件顺序清除了独占状态

助手的事件顺序是 `seized → starting → connected → ready`。曾把 `connected` 也当作清除独占标记的事件，导致独占刚建立就被复位，整个会话映射全被挡住、只剩语音键（ATVV 独立通道）可用。修复：`connected` 只是刷新连接绑定，独占由助手持有、跨连接持续有效；仅 `disconnected` / `stopped` / `error` 清除标记，随后的补独占事件再置回。

## 验证

- **真实数据回放**：用完整的 HCI 抓包（734 行）喂给新解码器，19 次按键（含 YouTube×3、主页×2 重复）全部正确解出按下/释放；
- **单元测试**：96/96 通过（新增 30 项第二布局检查：17 键解码、和弦、间距格式、未知码拒绝、异常长度拒绝、与旧布局互不干扰）；
- **实机验收**：14 键映射全部实际生效（返回→⌫、方向、OK→Return、音量、YouTube→F9、Netflix→F10 等），语音链路不受影响。

## 对使用者与上游的含义

- 只叫"Chromecast Remote"、能配对，不等于按键协议与首批一致；协议常量不能当作跨设备事实，`0x0046` 的教训已写入 [PROTOCOL.md](PROTOCOL.md)。
- macOS 26 的独占收紧影响**所有**在新系统上使用本项目的用户，与遥控器批次无关；该路径此前在 macOS 15.8.2 验证通过，新方案对旧系统同样成立（root 独占一直被允许）。
