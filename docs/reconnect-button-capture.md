# 普通按键断线恢复

症状：蓝牙断开后语音重新连上，普通按键却无响应；返回键配置仍为 Backspace。PacketLogger 在启动时输出设备 UUID 与连接 handle 的快照，持续运行时的重连并不保证重复输出该快照。解码器正确拒绝未知连接，导致旧会话永久失去普通按键。

修改：未绑定时最多每 5 秒重启已验证的私有 PacketLogger 子进程，重新读取选定 UUID 的快照。不根据设备名猜测身份，不重新申请管理员权限，不重启语音连接。以代次标识隔离旧子进程的输出和退出回调。停止、父进程退出及错误仍使用同一设置恢复路径。界面断线时清除就绪状态；绑定选定设备后才显示就绪。

验证：215 项检查全部通过，应用与助手构建和签名验证通过。本地安装后自动绑定成功；用户单按返回键，测试文本 ABC123 精确变为 ABC12。物理断线后的自动恢复仍需后续实机覆盖；本次回归覆盖刷新节流、绑定时不中断，以及旧连接拒收、指定 UUID 重绑定。

## 刷新后独占状态丢失（1.0.2 修复）

症状：语音键一直正常，普通按键日志显示「按下 → 映射」却无动作；事件流里最后一次「等待遥控器重连，正在刷新连接绑定…」之后只有 connected/ready，没有新的 seized。

根因：遥控器省电频繁断连，解码器失绑后助手按 5 秒节流重启 PacketLogger 并发送 disconnected；应用端据此清除 helperSeize。但刷新只重启 PacketLogger，root 助手的 HID 独占从未释放，也不会产生新设备实例的 matching 回调，因此没有 seized 补报——映射被永久暂停，直到下次恰好出现新 HID 实例。

修改：①刷新成功后与解码器重新绑定（connected）时，只要 seizedHIDs 非空就重报 seized；②注册 IOHIDManager 设备移除回调，断开的旧实例及时关闭并移出列表（此前 seized 计数随重连无限增长，实测 80 分钟 13→16）。应用端状态机不变：disconnected 清除、seized 恢复。

验证：单元测试全量通过；实机验收方法——开启按键接收后等待/触发一次连接刷新，事件流应在 disconnected 后出现 seized 补报，随后普通按键恢复执行（日志「按下 → 映射」且目标应用有动作）。
